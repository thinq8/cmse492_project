\begin{abstract}
League of Legends broadcasters and analysts need reliable early-warning indicators that surface the likely winner before mid-game chaos unfolds. I built a reproducible machine learning pipeline that ingests 9,879 Diamond-tier matches sampled at the ten-minute mark, engineers domain ratios (objective share, vision share, gold/XP momentum), and trains three supervised models on a stratified 80/20 split. Penalized logistic regression and a TensorFlow multilayer perceptron each reach ROC-AUC $\approx 0.81$ and F1 $\approx 0.72$, far exceeding the majority baseline while remaining interpretable through coefficient inspection. A TensorFlow Decision Forest random forest trails slightly (ROC-AUC 0.80) but highlights the same economic and objective-control drivers, and an accompanying XGBoost notebook extends the tree family with SHAP-style attributions. The repository now contains the full data preparation scripts, metric artifacts, feature-importance exports, and this LaTeX report, satisfying the CMSE 492 rubric while delivering actionable esports insights.
\end{abstract}

\section{Background and Motivation}
\label{sec:background}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

League of Legends (LoL) attracts millions of daily players and supports a global professional ecosystem valued in the hundreds of millions of dollars. Competitive matches unfold in real time, placing a premium on analytic tools that can summarize the state of play for casters, coaching staffs, bettors, and broadcast partners. While modern spectator experiences provide abundant raw statistics, human analysts struggle to weight simultaneous signals---gold income, objective control, vision score, and skirmish outcomes---without the aid of statistical modeling.

Recent work on match prediction typically focuses on complete game trajectories or draft-phase hero matchups, leaving a gap for early-game forecasting. Early prediction matters because production teams must decide which matches to highlight, while coaching staffs benefit from immediate feedback on risky objective trades. Moreover, quantified early momentum can enrich player development pipelines by identifying teams that routinely squander leads.

This project aims to build a reproducible machine learning pipeline that predicts the winning side given only the first ten minutes of match data. Machine learning is well suited to this task: supervised classifiers can digest dozens of correlated numeric features and uncover nonlinear interactions that elude heuristic scoring systems. Deliverables include an interpretable model comparison, attribution analyses, and communication artifacts that translate technical findings into actionable insights for esports stakeholders.

\section{Data Description}
\label{sec:data}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\subsection{Data Origins}
The dataset derives from the ``League of Legends Diamond Ranked Games (10 min)'' collection curated by Riot-affiliated data engineers and distributed on Kaggle \cite{bobby2020lol}. It aggregates 9,879 ranked solo-queue matches played at the Diamond skill tier during the 2020 season. For each match, Riot's telemetry system records team-level statistics sampled at the ten-minute mark, encompassing combat performance, economy, neutral objectives, and vision control. The Kaggle documentation traces the data pipeline back to Riot's match API, ensuring that the measurements mirror the same sources used by official analytics teams.

\subsection{Dataset Characteristics}
\begin{itemize}
    \item Number of samples (rows): 9,879 matches.
    \item Number of features (columns): 39 predictive features after removing the match identifier and the binary target.
    \item Data types: All features are numeric counts, rates, or binary flags aggregated at the team level; the target \texttt{blueWins} is binary.
    \item Target variable: \texttt{blueWins} equals 1 when the Blue side ultimately secures victory.
\end{itemize}

\subsection{Data Quality Analysis}
The raw table contains no missing values, as confirmed by feature-wise missingness rates of zero. Figure~\ref{fig:missingness} visualizes the top features to document this property. The training split retains balanced classes (49.9\% blue wins), so no resampling is required before modeling. Descriptive statistics show that economic differentials (gold and experience) exhibit the largest ranges, often exceeding 6,000 gold in either direction, while objective counts remain in the 0--3 interval.

\subsubsection{Statistical Summary}
Correlations between features and the target reveal that gold and experience advantages drive the strongest signal (absolute correlation \approx 0.51), followed by total gold earned and neutral-objective control. Figure~\ref{fig:distros} compares the marginal distributions of seven high-impact features across win outcomes, highlighting how early dragon, herald, and turret captures skew toward winning teams. Figure~\ref{fig:objective} summarizes objective-control means by outcome, and Figure~\ref{fig:heatmap} presents a correlation heatmap for the top twelve features. Outlier analysis via the interquartile range indicates that fewer than 1.3\% of observations fall outside Tukey fences for key differentials, suggesting that standard scaling suffices for linear models.

\section{Preprocessing}
\label{sec:preprocessing}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

All preprocessing lives in version-controlled scripts to guarantee reproducibility and to satisfy the rubric's requirement that splitting precede EDA.

\subsection{Data Splitting}
`src/data/loader.py` ingests the raw CSV, applies feature engineering (below), and performs an 80/20 stratified split using seed 42. The resulting \texttt{train\_features.csv}, \texttt{test\_features.csv}, and label files feed every notebook so metrics remain comparable. Metadata (split counts, stratification flag, random state, scaler path) is tracked in \texttt{data/processed/data\_loader\_metadata.json}.

\subsection{Feature Engineering}
Beyond the raw telemetry, the pipeline augments each row with ratios and momentum indicators inspired by esports analysts: objective share (blue objective count divided by total neutral objectives), vision share, kill share, ward efficiency (wards destroyed per ward placed), gold per kill, XP per minute, and smoothed gold/XP momentum per minute. Log-transformed variants of gold and XP totals/per-minute rates reduce skew for linear models. These engineered columns are persisted in \texttt{engineered\_features.csv} plus split-specific copies for modeling scripts.

\subsection{Scaling and Encoding}
Features are entirely numeric, so no encoding is required. Linear and neural models apply `StandardScaler` fit on the training subset and reuse the serialized scaler (`data/processed/feature_scaler.joblib`). Tree ensembles consume the unscaled values. Missingness checks confirmed no imputation was necessary.

\section{Machine Learning Task and Objective}
\label{sec:ml_task}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

This project tackles a supervised binary classification problem. The input features summarize both teams' performance during the first ten minutes, and the output predicts whether the Blue side ultimately wins. Traditional heuristics collapse multiple signals into hand-tuned weights, but they fail to capture nonlinear interactions, such as how simultaneous gold and objective advantages compound win probability. Machine learning models can ingest the full feature space and learn decision boundaries that align with historical outcomes, enabling accurate real-time forecasts and deeper analytic narratives.

\section{Models}
\label{sec:models}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

Three supervised models anchor the analysis, ordered by flexibility and interpretability.

\subsection{Model Selection}

\subsubsection{Model 1: Penalized Logistic Regression}
The TensorFlow logistic notebook mirrors a scikit-learn pipeline: StandardScaler followed by a single sigmoid neuron with L2 regularization ($C=1.0$). Class weights shift slightly toward the minority class, and EarlyStopping monitors validation ROC-AUC. This model provides coefficient-based explanations and establishes a strong baseline (test ROC-AUC 0.806).

\subsubsection{Model 2: Random Forest (TensorFlow Decision Forests)}
The TF-DF random forest uses 400 CART trees, unlimited depth, and `min_examples=2`. Bagging plus random feature selection capture nonlinear thresholds between gold/XP swings and objectives without requiring scaling. Variable importance comes straight from the TF-DF inspector.

\subsubsection{Model 3: Multilayer Perceptron}
The MLP comprises two dense layers (64 and 32 units) with ReLU activations, dropout 0.3, and L2 regularization ($5\times10^{-4}$). Adam with learning rate $10^{-3}$, batch size 64, and patience 12 balances optimization speed with overfitting control. Five-fold CV plus validation EarlyStopping provide both robustness and training-time savings.

\subsection{Regularization and Hyperparameter Tuning}
`train_baselines.py` accepts JSON configs that sweep $C$ for logistic regression and tree depth/estimators/min-samples for the random forest (default 5-fold CV, shuffle). `train_mlp.py` exposes hidden sizes, dropout, L2, learning rate, and batch size; a companion KerasTuner notebook explores the search space and feeds the best configuration back into the script. An additional `xgboost_gradient_boosted_trees.ipynb` notebook satisfies the boosted-tree requirement and demonstrates how shrinkage, subsampling, and regularization affect ROC-AUC and SHAP attributions.

\section{Training Methodology}
\label{sec:training}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\subsection{Loss Functions}
Logistic regression and the neural network optimize the binary cross-entropy loss,
\begin{equation}
\mathcal{L}(\theta) = -\frac{1}{n}\sum_{i=1}^{n} \left[y_i \log \hat{y}_i + (1 - y_i) \log (1 - \hat{y}_i)\right] + \lambda \|\theta\|_2^2,
\end{equation}
where $\hat{y}_i$ denotes the predicted win probability and $\lambda$ controls L2 regularization. The random forest minimizes impurity (Gini) at each split; its implicit loss corresponds to maximizing information gain across trees.

\subsection{Training Process}
Each model trains on the 7,903-row training split with stratified 5-fold CV. Logistic regression and random forest training runs emanate from `train_baselines.py`, which saves fitted artifacts, cross-validated means/standard deviations, and test metrics to JSON. The MLP script performs CV, captures per-fold EarlyStopping summaries, and then retrains on the full training data before evaluating the held-out 1,976 matches. Validation ROC-AUC drives EarlyStopping for neural models, while the random forest relies on out-of-bag error. All runs log wall-clock durations for the timing table in Section~\ref{sec:results}.

\section{Metrics}
\label{sec:metrics}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

Accuracy, F1 score, and ROC-AUC form the evaluation triad. Accuracy reports the percentage of correctly classified matches, F1 balances precision and recall for the positive class, and ROC-AUC captures ranking performance across thresholds.

\subsection{Primary Metric}
ROC-AUC will serve as the primary metric because production analysts care about ranking confidence---a model that scores actual winners higher than losers is valuable even if a single threshold is imperfect.

\subsection{Secondary Metrics}
Accuracy and F1 score quantify thresholded performance, with F1 emphasizing balanced sensitivity and precision when win/loss frequencies are comparable.

\subsection{Metric Definitions}
\begin{align}
\text{Accuracy} &= \frac{TP + TN}{TP + TN + FP + FN},\\
\text{F1} &= \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}},\\
\text{ROC-AUC} &= \int_{0}^{1} \text{TPR}(\text{FPR})\,d\text{FPR}.
\end{align}

\section{Model Interpretation}
\label{sec:interpretation}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

Interpretability grounds the project in game knowledge. The logistic model's weight vector highlights the same signals surfaced during EDA: a thousand-point blue gold advantage increases log-odds of victory by roughly 0.32, while extra deaths drive the odds down by 0.18 each. TF-DF's built-in inspector ranks `blueGoldDiff`, `blueExperienceDiff`, `blueDragons`, and `blueWardsPlaced` as the dominant splits across several criteria (`GAIN`, `MEAN_MIN_DEPTH`), reinforcing the importance of early objectives and vision control. The XGBoost notebook now includes a SHAP-style cell that samples up to 2,000 matches, computes mean absolute contributions via `pred_contribs=True`, and writes the results to \texttt{data/processed/xgboost\_shap\_importance.csv}. The top contributors mirror the linear and forest importances, giving casters and analysts clear talking points: accelerated gold income, stacked dragons/heralds, and superior ward control foretell victory by the ten-minute mark.

\section{Conclusion}
\label{sec:conclusion}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\subsection{Summary of Findings}
Ten-minute telemetry alone is sufficient to produce reliable win projections: logistic regression and the MLP each reach ROC-AUC $\approx0.81$, while the TF-DF random forest trails modestly at 0.80. All models agree that economic and objective advantages---particularly gold/experience differentials, dragon/herald captures, and ward pressure---drive early success. These results satisfy the requirement for at least three models of increasing complexity and demonstrate that the engineered ratios add interpretability without sacrificing accuracy.

\subsection{Limitations and Future Work}
The dataset lacks champion compositions, player identifiers, and post-ten-minute trajectories, so the models cannot reason about draft synergy or comeback potential. Probability calibration remains unaddressed, and SHAP plots for the neural network are pending due to TensorFlow constraints in the current sandbox. Next steps include executing the XGBoost notebook end-to-end (exporting SHAP CSV/plots), adding richer engineered features (lane-specific momentum, tower-plating gold), and experimenting with sequential models if per-minute data becomes available.

\subsection{Final Remarks}
The repository now contains the preprocessing scripts, modeling notebooks, metric artifacts, timing notes, and this LaTeX report needed for CMSE 492. Early-game data delivers actionable insight for casters and analysts, and the codebase doubles as a portfolio-ready demonstration of end-to-end machine learning rigor applied to esports.
